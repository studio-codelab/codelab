Adresse mail
Adresse mail
L'adresse rattachée à ton compte.
 
Un code à six chiffres est envoyé à cette adresse pour vérifier que tu la relèves vraiment. Cette vérification ne remplace pas le second facteur et n'ouvre aucune session : elle atteste seulement que l'adresse est la tienne.
Aucun serveur d'envoi n'est configuré sur ce serveur : la vérification par mail est indisponible pour le moment.

Double authentification
Un code à six chiffres, en plus du mot de passe, à chaque connexion.
 
Le mot de passe est un secret unique : s'il fuit, il donne l'exécution de commandes sur cette machine. Le second facteur exige en plus ton téléphone. À activer avant d'exposer ce panneau au-delà de ton réseau.
1. Scanne ce code avec ton application d'authentification.
Ou saisis la clé à la main :
2. Saisis le code affiché par l'application pour confirmer. Rien n'est enregistré tant que ce code n'est pas valide — une clé mal recopiée ne peut donc pas t'enfermer dehors.
Pour désactiver, saisis un code valide : une session volée ne doit pas pouvoir retirer le second facteur.
Clés d'accès
Clés d'accès (passkeys)
Se connecter avec l'empreinte ou le code de son appareil.
 
Une clé d'accès remplace le mot de passe et le code à six chiffres : l'appareil prouve la possession, et l'empreinte (ou le code de l'appareil) prouve que c'est bien toi. Rien à retenir, rien à recopier — et rien à hameçonner, puisque la clé ne signe que pour le domaine qui l'a enregistrée.
Pour la reconnaître dans la liste, le jour où tu en auras plusieurs.
Serveur
Derrière un proxy, en HTTPS
Les deux réglages qui suivent le passage du panneau sur internet.
Une case ne s'active que si la situation la justifie — sinon elle reste grisée et dit pourquoi. C'est délibéré : activer HTTPS depuis une page servie en clair poserait un cookie « Secure » que ton navigateur cesserait d'envoyer, et te déconnecterait sans retour possible. Les éteindre, en revanche, est toujours permis.
Liaison avec un VPS
Un VPS devant, un tunnel derrière, et rien d'ouvert sur ta box.
 
Le VPS porte le nom de domaine et le certificat ; cette machine ne publie rien sur internet et reste joignable seulement par le tunnel. Saisis les deux valeurs ci-dessous et le panneau produit les fichiers de configuration, prêts à copier. Il ne se connecte pas au VPS : lui donner une clé SSH avec les droits qui vont avec ferait de ce panneau la cible la plus intéressante de l'installation.
Trois nombres. N'importe quel réseau privé inutilisé chez toi convient ; garde 10.8.0 si tu n'as pas de raison d'en changer.

Adresse publique
L'adresse par laquelle ce serveur est joignable depuis internet.
 
Tant qu'elle n'est pas déclarée, le panneau ne propose pas de rendre une application publique : sur un serveur que personne d'autre ne peut joindre, « publique » ne partagerait rien — cela retirerait seulement l'authentification. Une application déjà publique n'est pas touchée, et peut toujours être refermée.
Elle se déclare à la main : le panneau ne peut pas savoir si le port 443 de ta box est ouvert, si ton tunnel tourne, ni quel nom de domaine y mène. La renseigner, c'est dire « j'ai fait le nécessaire ».
Vide = serveur privé, joignable seulement depuis ton réseau.
Cette adresse est fixée par APP_MANAGER_PUBLIC_URL dans le compose : elle se modifie là-bas.
Catégories
Catégories du hub
Des tiroirs pour ranger les projets sur la page d'accueil.
Une catégorie ne donne aucun droit et ne change rien au déploiement : elle regroupe les projets dans le hub, dans l'ordre de cette liste. Un projet sans catégorie apparaît à la fin, sous « Autres ». Choisis la catégorie d'un projet dans sa fiche, onglet Configuration.
E-mail
Serveur d'envoi (SMTP)
Par où sortent les mails de CodeLab.
 
Trois choses en dépendent : les alertes quand une application tombe, les codes de vérification des adresses mail des comptes, et l'inscription libre — qui reste fermée tant qu'aucun serveur n'est configuré, faute de pouvoir vérifier une adresse.
Laisse vide pour conserver celui déjà enregistré. Gmail exige un mot de passe d'application, pas ton mot de passe habituel.
A l'enregistrement, CodeLab se connecte réellement à ce serveur : chiffrement et authentification compris. Une configuration qui ne répond pas n'est pas enregistrée, et le message du serveur t'est rendu tel quel. Rien à lancer à la main, rien à penser à vérifier.
Configuration d'origine
Celle de credentials.env. Elle ne bouge jamais.
 
Posée à l'installation, elle sert de repli : si la configuration ci-dessus cesse de fonctionner — mot de passe révoqué, quota atteint, serveur éteint — les mails repartent automatiquement par celle-ci. Le panneau ne l'écrase jamais, c'est pour cela qu'on peut lui faire confiance.

Expéditeur —
Elle se modifie dans le bloc codelab-alertes de credentials.env, sur le serveur. Le capteur d'alerte de Dagster lit le même bloc.
Adresse d'alerte de l'administrateur
Celle qui reçoit tout, quelle que soit l'application.
C'est le filet. Chaque application peut avoir ses propres destinataires (dans sa fiche, onglet Configuration), mais cette adresse-ci les reçoit toutes — y compris celles des applications dont la liste est restée vide. Sans elle, une application oubliée tomberait en silence.
Plusieurs adresses possibles, séparées par des virgules.
Alertes
Alerte par mail
Un mail quand une application tombe, un autre quand elle revient.
 
Le panneau redémarre tout seul une application qui plante. Il abandonne au bout de 5 tentatives en 10 minutes — c'est à ce moment-là que le mail part, pas au premier soubresaut. Un second mail signale le retour à la normale.
Message
Un mot à l'administrateur
Une gêne, une idée, une application qui manque.
Ton message part par mail à l'administrateur du serveur et reste dans le panneau. Il porte ton nom de compte : c'est ce qui lui permet de te répondre.
2000 caractères au maximum.
